# 反调试、反沙箱与条件触发样本

一次动态任务未观察到异常，不能据此将样本判定为安全。平台需要分别记录任务是否执行完成、采集是否完整、可见行为、反分析线索与尚未覆盖的条件。AI 判断不是执行证据。

## 本版本已经提供

- 隔离静态工作器识别有限 ASCII 字符串：调试检测 API / TracerPid / ptrace、部分虚拟化标记、计时与用户活跃度 API。结果包含原始文件偏移，脚本还含原文行号；注释或正常代码中的字符串仍只是线索，不升级为已执行的逃逸行为。
- 元信息固定列出未覆盖项：API 哈希与动态解析、混淆 / 加密 / UTF-16、时钟指令、内核与硬件检测、动态内存及多环境对照。没有命中时标记能力未知，不是检查通过。
- Pi 可据这些线索继续核对源码与入口反汇编，保留待复核判断。没有自动去除反调试、补丁样本或执行未知代码的工具。
- 动态任务界面显示「观察受限」，现有 Docker / CAPE 报告保留环境、时限、截断与反分析限制。Linux Docker 为短时系统调用观察；不提供完整可信行为链。

## 深度样本的调查方法

1. 静态定位条件与证据：先确定文件格式、架构、入口、导入、字符串和解码层。分析调试器 / 虚拟化检查、日期与等待条件、网络可用性和外部配置依赖。无法恢复的分支明确保留未知，不能靠改系统时间或拉长任务假装覆盖。
2. 使用多份独立、可回滚的专用 VM 对照正常启动与受监控启动，保留样本 Hash、系统版本、快照、时间、采集手段、网络策略及结果差异。普通本机 Docker 不能替代这些 VM；跨环境的反差只是线索，仍需排除架构、依赖库和配置不兼容。
3. 当进程内插桩或调试器可能改变行为时，由专用实验环境提供来宾外的网络记录、磁盘差异或虚拟机监视层观察，再与来宾内进程 / 文件 / 注册表记录交叉核对。每种观测方式都有盲区，不能声称绝对不可检测。
4. 处理延迟、用户操作和联网触发：按已定位条件设计独立实验，记录是否实际满足。受控网络模拟可帮助观察请求与响应依赖，不直接放行未知样本到公网。时间改动本身可能改变行为，应单独记录实验条件。
5. 关联真实被入侵主机的 EDR、事件日志、启动项、进程树、连接记录和依法获取的内存 / 磁盘证据；对照沙箱结果。原始内存与文件的解析也应送往隔离工作器。
6. 若仍无行为，结论应为「本次未观察到；反分析或触发条件未排除」，列出下一步取证与覆盖缺口。条件允许时可由分析员在专用 VM 做定向调试；修改后的样本必须独立归档，不能把修改后行为当作原样本的已发生行为。

多环境自动编排、来宾外采集、受控网络模拟、内存取证与 Ghidra 反编译尚未在本客户端实现。需要外部专用实验设施及实机验收后才可接入；Windows CAPE 当前仍缺真实 VM 联调。以上方法是后续调查策略，不是本版已经完成的功能清单。

## AI 的职责

AI 适合按线索请求工具、比较多次实验工件、整理条件分支与证据缺口，并将观察写入报告第 3 步。隔离边界、样本归属、Hash 校验、工具权限和结论的证据要求由确定性程序与人工复核负责。模型不能将空结果解释为安全，也不能自行扩大权限、联网或在宿主机运行样本。
