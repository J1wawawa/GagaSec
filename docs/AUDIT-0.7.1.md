# 0.7.1 深度审计与增量验收

2026-10-28，macOS arm64。定位不变：面向防御团队、运行在个人 PC 上的一站式安全终端。审计检查了报告、归档、维护、调度、流量解析、模型材料/引用及隔离边界。仅对下列可复现问题做了修改，没有把静态阅读等同于全面运行证明。

## 复现与修复

| 编号 | 修改前的可复现行为 | 修复与验证 |

| A071-02 | 指针更新先删后改；删除后中断留下 previous，启动却可能回默认工作区 | 报告和指针共用 file_commit，同目录唯一临时文件、sync 后替换。没有预先删除；缺主指针但有 previous 明确报错。注入写入失败和替换失败后旧文件保留，临时文件清除；实机连续选择保留 previous |

修改前保留了 4 个失败 Rust 用例和 1 个失败 Go 用例的输出。A071-04 的运行中重新启用检查及共享提交失败检查是修复后的附加验证。没有把检查断言数量当成检测准确率。

## 架构改动

新增 file_commit.rs，报告和工作区指针复用文件写入/替换策略，避免各自实现先删除和固定临时名。report.rs 复用 logbook 的流式归档校验；大原件不会全量读进内存，但导出会增加实际 Hash I/O，尚未测量该步骤对 1 GiB 导出的耗时。维护页读取后端真实占用，结构版本不再写死。

没有修改数据库结构（仍为 user_version=1）。现有工作区可直接读取，工作区切换仍仅对下次启动生效。隔离 Worker/Pi 镜像仍是 0.7.0 的兼容实现，客户端和新 Agent 模板作为 0.7.1 交付。C4 见 [C4-architecture-0.7.1.md](C4-architecture-0.7.1.md)。

## 下一轮需要优化和验证的项目

- Workspace 聚合会加载当前事件全部证据摘要；需要多事件、长时间巡检与多证据基准后分页。单日志吞吐不代表整体容量。
- AI 引用列表当前覆盖已归档发现，不严格等于本次发送片段；应为引用建立片段级允许集和独立预算。实际来源存在不保证其支持模型结论。
- 提示注入和复杂混淆需要独立保留集与多模型回归；现有系统提示、工具权限和结构校验不构成抗注入保证。
- 巡检自动 AI 会处理待分析历史队列；启用前应更清楚展示积压、外发范围和预算，目前不是只分析启用后新观测。
- 主机明文证据、凭据迁移、团队认证、司法级签名、真实目标长期网络、Windows/CAPE、另外三家官方模型仍需单独工作。
- macOS 交付是 ad-hoc 开发包，未 Apple 公证；Windows MoveFileExW 分支未实机验收，网络盘/断电持久性没有保证。远端 CI 未执行。
- 本轮不重复依赖数据库扫描；0.7.0 仍有 5 个 Rust 包匹配公告，见 [DEPENDENCY-REVIEW-0.7.0.md](DEPENDENCY-REVIEW-0.7.0.md)。源码改动不代表这些公告已经消失。

go vet ./...
