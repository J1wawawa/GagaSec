# 0.7.2 深度审计与社区可用性改进

2026-10-29，macOS arm64。定位保持为面向防御团队、运行在个人 PC 上的一站式安全终端。本轮重点是材料外发、事件授权、引用可核对性和首次源码使用。没有将新增设置或测试数量当作全面安全证明。

## 实际问题与修复

| 编号 | 修改前行为 / 缺口 | 当前实现与验证 |
|---|---|---|
| A072-01 | 启用监控自动 AI 后，会领取启用前已经存在的 pending 观测；授权没有限制到一个事件 | 后端捕获当前事件、数据库插入边界和新授权 revision。只领取之后插入的该事件观测；历史积压保留人工选择。旧版授权需重新确认。伪造范围、其他事件、旧 revision、并发预算与时间回拨回归通过 |
| A072-02 | 引用允许列表取自整份归档，即使某发现没有进入本次发送材料，仍可能被 Prompt 宣传和结果接受 | Prompt 0.4.0 与响应解析共用本次材料的允许集，限制来源项数和字符预算。未发送发现不进入允许集，模型返回的范围外引用剔除并保留提示；引用存在仍不等于推断成立 |
| A072-03 | 敏感客户场景缺少集中、可持久保存的 AI 暂停控制；联网路径说明分散 | 新增 privacy.rs、独立设置页和工具栏状态。锁定停用自动 AI，研判、追问、连接测试、Pi 启动/模型代理均检查。凭据读取前与等待后检查；配置损坏时拒绝。解锁不恢复授权，本地工具和报告仍可用 |
| A072-04 | 全新源码直接开发启动可能尚未生成 Agent 模板，之后生成任务失败 | beforeDevCommand 先运行 build:agents，再启动 Vite；与打包流程一致，README/QUICKSTART 明确工具链和本地功能前提 |
| A072-05 | 源码交付缺少统一的本机材料误提交检查 | 新增 check:source、test:source-check 和 CI 步骤，检查 tracked 文件或干净源码目录。数据库、本机配置、常见 Key、非公开私钥和生成模板等被拒绝；固定公开测试私钥按路径和摘要同时限制，不输出匹配值 |

修复前实际执行了两个失败回归，分别复现历史观测被领取和未发送来源被宣传，原始输出保留在 regressions-before.log。其余为新增控制和补充故障边界，不虚构修复前利用结果。

## 架构与使用行为

没有改变 SQLite user_version=1；授权及隐私为工作区 settings，新增字段通过 serde(default) 兼容旧记录。锁定与停用自动 AI 使用同一事务；自动领取将授权复核、预算检查、领取和 ledger 写入合并事务。插入边界避免时间回拨导致历史材料重新授权。完整数据流和时序见 [C4-architecture-0.7.2.md](C4-architecture-0.7.2.md)。

隐私页面与工具栏保持黑白双主题，最低 960×660 窗口验证了可见布局与无横向溢出。隐私 hook 先订阅事件再读取快照，避免挂载时丢失更新；旧读取不覆盖较新的事件。此类界面回归不能代替社区用户的实际可用性评估。

AI 外发锁不是防火墙，不撤回已进入发送阶段的数据。它不控制资产抓取、Agent 回传、Docker 镜像访问或 CAPE 原样本上传。解锁后必须重新授权自动 AI；一次授权一个事件，切换界面事件不扩大授权，原授权事件可以继续在后台处理新观测。领取后的任务可能继续完成，小时预算统计尝试而非官方账单。详见 [PRIVACY.md](../PRIVACY.md)。

## 验收记录

本轮交付附带原始日志、原生 IPC 调用计数及物理工件检查。最终通过数、模型请求数与安装包摘要以随包 verification.json 为准；历史结果明确另列。

已经完成的基础检查：103 项 Rust 测试、Clippy -D warnings、rustfmt、TypeScript/Vite、Prettier、10 项前端状态断言，以及六项源码检查故障测试。新增的原生隐私/报告/恢复验收首次 35 项、重启 5 项，物理工件 19 项：实际 Docker 无害 PHP/ELF 静态分析、外发锁拦截、取消清理、草稿恢复冲突、截图粘贴、HTML/DOCX 嵌图、原件篡改拒绝、备份恢复和重启持久化。

综合工作台 181 项界面检查、11 项持久化/传输检查通过，使用真实回环固定模型服务，不算官方模型效果。实际固定证书 HTTPS 回传返回 202；10 个资产后台运行两轮，共 20 份 HTML/JS 快照，首轮约 10.3 秒、第二轮约 75.3 秒，配置间隔 60 秒。该测试证明本机调度流程，不能代替外网长期巡检。

独立原生导航 115 项通过，覆盖任务入口、工具搜索、键盘导航与双主题窗口布局。原生深度和导航测试均在最终签名的 0.7.2 二进制上运行；交付记录保存其 SHA-256，再检查压缩包解压后的可执行文件相同。源码 ZIP 也需解压后再次执行源码检查。

本轮尝试使用已有 DeepSeek 配置元数据和系统凭据做原生官方验证，连接测试 30002ms 后明确失败：“读取系统凭据超过 30 秒，尚未发送模型请求”。实际官方请求为 0、完成研判为 0。未读取导出真实 Key、未修改钥匙串 ACL，也没有把配置标记 hasKey 当作凭据确实可访问的证明。0.7.0 的官方 DeepSeek 结果只保留为历史；0.7.2 的官方兼容验收仍需用户在系统授权或重新保存 Key 后完成。

原生测试曾暴露两处测试自身问题，保留失败记录后修正：隐私页挂载前对空元素调用 getComputedStyle；综合测试写死旧 Prompt 0.3.0。前者等待元素出现，后者改为解析界面真实 JSON 并与保存的 model、promptVersion、requestMessages 比对，没有通过删除断言掩盖失败。

综合测试另有一次直接执行 macOS bundle 二进制超时，最后检查点在事件编辑。改用与深度/官方测试相同的 Launch Services 启动，并将整条综合流程等待上限从 150 秒调整为 300 秒后通过，未修改事件编辑产品代码。未单独证明超时根因，保留原日志；不能将这次通过解释为所有启动/焦点问题均已消除。

Go 逻辑、eBPF 和大日志处理本轮未修改：0.7.1 的 Go vet/race、真实 LinuxKit 回环采集，以及 0.7.0 的 128 MiB/1 GiB 日志与完整案例属于历史验收，本轮不重复计为新结果。Agent 三目标模板随当前构建生成；构建不代表 Windows 实际运行。

## 未覆盖与后续优先级

- Windows GUI/Agent/凭据/文件替换、CAPE 真正的 Windows VM、Qwen/GLM/Kimi 官方请求仍待对应环境验收。
- 明文工作区、认证协作、可信签名和完整证据链未实现。Hash 核对不能抵抗同时修改数据库与原件的人。
- 普通 Docker 共享内核；只运行合成/无害样本，不用实际木马测试。真实不可信样本应在专用可回滚 VM；没有反沙箱绕过或复杂混淆全面检出承诺。
- 本轮没有重扫依赖公告数据库；0.7.0 审阅的 5 个 Rust 包匹配仍按原状态保留，见 [DEPENDENCY-REVIEW-0.7.0.md](DEPENDENCY-REVIEW-0.7.0.md)。容器完整 SBOM 与基础镜像来源验证仍需补充。
- 优先补多事件分页和容量基准、大文件校验进度/取消、离线规则包版本来源管理、人工可审阅的分享包。当前不具备长时间真实客户监控和千事件压力验收。
- macOS 为 ad-hoc 签名的开发预览包，未 Apple 公证；不保证所有文件系统故障/断电条件下的持久性，不承诺零 Bug。

## 复现入口

```sh
npm ci
npm run check:source
npm run test:source-check
npm run format:check
npm run test:ui-state
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --locked --manifest-path src-tauri/Cargo.toml
npm run desktop:build:mac-dev
```

离线构建可使用已有缓存和 --offline，本轮 Cargo 使用独立 CARGO_TARGET_DIR。原生 scripts 使用独立工作区；深度测试只复制模型配置元数据，不复制 Key，Pi 在官方请求前取消。官方模型测试使用系统凭据和合成材料，固定回环模型测试不能计为官方效果。
