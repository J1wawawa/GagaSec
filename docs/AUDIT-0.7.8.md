## PDF 如何交付

先保存正文并检查章节、引用、时间胶囊和截图，再生成 HTML/DOCX 或打开系统打印保存 PDF。**打开打印窗口不表示保存成功**；系统取消/保存路径无法通过当前 IPC 获知。

保存后在电子水印区域查询 PDF；必要时另存带水印副本，核对可解析页数和结果。最终用 Preview / Acrobat 等实际阅读器检查跨页、图片和文字，再流转文件。水印不改变可见排版，不是第三方数字签名或不可删除标记；重新打印、清理元数据等可能移除水印。

程序对损坏 PDF、签名 PDF、过大文件、内部路径和原件 Hash 不一致作明确拒绝。导出失败可查看任务错误与设置日志，不以错误重试自动删除原件。日志也有不可写/强杀等边界，见 [日志说明](LOGGING.md)。

## 架构、规范和剩余工作

Rust 按领域模块组织，关键注释覆盖取消/提交顺序、事件归属、密钥、网络截止时间与日志隐私。本轮抽出前端统一 bridge 和错误边界；主工作台 main.tsx 仍约 3500 行，后续需要继续拆分，不能称“所有架构优化完成”。文档见 [当前 C4](C4-architecture-0.7.8.md) 和 [IPC 契约](IPC-API.md)。

以下仍须明确：

- 事件数据库与原始证据未整库加密；只读/Hash 不能抵抗有权限同时修改数据和索引的人。LAN 正文与附件单独加密，密钥仍受本机文件权限保护。
- Mac 安装包为 ad-hoc，未 Developer ID 签名/Apple 公证；正式公开发行前仍需真实发行资质和公证流程。
- Windows / CAPE、双物理设备、不同路由/访客网、四家官方模型完整端到端仍未在本轮验收。没有把旧版本模型实测冒充本轮结果。
- 动态样本应在专用、可回滚隔离 VM；Docker 共享内核。AI、规则未命中或未观察到行为均不能单独证明安全。
- 源码许可为个人及非商用免费、商用须 J4team 授权，不是 AGPL 或 OSI 开源许可。没有完整依赖许可法律审查或外部渗透测试认证。

以上边界不会因断言数量增加而自动消失。公众发行应结合许可、发行签名、备份恢复和支持入口明确版本成熟度。
