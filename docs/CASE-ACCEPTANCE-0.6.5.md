## 报告结构

顶部独立「报告」入口，内含正文编辑、节点与截图、报告预览。

基本信息记录事件类型、发现时间、发现人、危害等级与概述。正文依次为：危害评估与影响范围、事件紧急处置、事件过程排查（包含木马分析）、攻击或威胁溯源、处置结果。每步记录负责人、开始 / 完成时间和状态，关联本事件节点并直接粘贴截图。未分章节节点进入时间线附录，旧版摘要、范围、结论与建议保留。

五步负责人均为本轮合成角色，不是已验证的团队账号。状态为人工填写，不能据此认定对应处置由软件自动执行或已获审批。

## 本轮发现并修复

1. 报告入口隐蔽且只有预览：独立一级入口，补基本信息、五步正文、负责人与步骤内证据 / 截图编辑。
2. 编辑节点说明丢失毫秒：未主动修改时间时保留完整原始时间，原生案例验证。
3. AI 脚本缺注释上下文、HTTP 缺消息头：补经 Hash 校验的有界源码及双侧起始行、消息头，保留凭据脱敏。实际 DeepSeek 将注释内惰性样本判为 benign。
4. 系统凭据等待误显示为模型推理：新增「系统凭据」阶段，移出异步执行线程，30 秒超时，相同时间仅一次读取。早期超时约 30004 毫秒，官方 API 步骤跳过，未伪造结果。
5. 直接运行 .app 内部二进制时凭据读取等待且没有可见授权弹窗：原生官方测试改为 macOS Launch Services 启动；最终版正常读取同一已保存 Key，完成 9 次真实研判和 1 次追问。没有要求重新提供或提取 Key。
6. 模型把「证据 ID + 行号」合成一条引用，解析器全丢弃：明确每项引用格式，仅兼容当前证据 ID 与已存在行号组合；拒绝外事件、虚构行号及任意索引后缀，原始回答仍留存。
7. 退出后遗留运行中状态：工作区重开时标为中断失败，不自动重试或生成成功结论。
8. 最小窗口下第五章节按钮超出可视区：短窗口压缩章节导航间距，六章节在三种尺寸与明暗模式均验证。
9. 开发 .app 包签名不完整：打包后本地 ad hoc 签名，codesign 校验。未作为 Developer ID 公证发行版。

## 官方 AI 实测与证据边界

最终案例请求使用 `https://api.deepseek.com` / `deepseek-flash`，共 9 次研判、1 次追问。每份保留发送材料、完整最终 Prompt、原始回答、结构化结果、阶段耗时与关联证据。所有研判能定位至少一项来源；结构化结果不保留模型自行声明的攻击成功。C 案例人工误报反馈与事件白名单留存，报文中的提示注入没有替换结构化分析。

模型 Key 仅在系统钥匙串，通过配置元数据用于隔离工作区；没有写入脚本、命令或案例包。先前失败尝试保留在工作目录，最终结果来自独立的新工作区。旧版本成功调用不算本版通过依据。

这些检查验证流程、保存、引用与导出可用性，不代表模型判定必然正确、ATT&CK 映射已核验或溯源归属可靠。对合成告警的模型分类仍需人工复核，不能把文档保留 IP 作为真实攻击情报。

PDF 是实际 HTML 导出的浏览器打印副本；原生系统打印 / 保存 PDF 对话框未自动化验收。本版无后台直接 PDF 渲染。

本轮没有执行真实恶意样本、扫描实际客户资产，或重跑先前 1 GiB 日志。Windows / CAPE、其余三家官方 API、真实 Linux eBPF、在线微步 / WHOIS 等仍需对应环境或实现。不能由本轮通过推断全部路线图已实现。
