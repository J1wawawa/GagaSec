# 嘎嘎安全助手 0.6.1：HTTP 录入与失败恢复修复

2026-10-28 · J4team

本次针对“HTTP 联合分析失败”修复复制录入的兼容性、错误显示与事件草稿归属，并交付新的 macOS 开发包。0.6.0 交付物保留。

## 已确认的问题

旧解析器要求起始行 / 消息头后必须有一个空行。用户从抓包工具复制纯请求头，或者复制时丢失尾部空行，即使起始行和头字段有效，也会整组失败。修复前新增回归用例实际失败，返回：`报文需要起始行、消息头及一个空行；正文可以为空。`

用户此次反馈只提供了通用状态“HTTP 联合分析失败”，没有原始输入或详细异常，因此无法断言该次失败一定只有这一原因。这个兼容性缺陷已复现和修复；新版也会在录入区显示具体错误，便于继续定位其他输入。

## 修改内容

- 允许只提供起始行和合法头字段，不再强制要求复制末尾空行；明确提示正文缺失 / 截断状态未知，不补造正文。
- 解析阅读视图兼容起始 BOM、起始空行和起始行多余空白；原文归档与 SHA-256 保留提交字节。完整报文的请求 / 响应规则与有界解码流程继续使用。
- 格式错误明确标注“请求包”或“响应包”。正文没有用空行分隔时给出修正说明，真正无效的输入仍拒绝。
- 错误显示在 HTTP 编辑器内，保留两侧输入，修正后可直接重试。UTF-8 字节超限在提交前明确指出对应侧。
- 空白编辑器增加“填入测试报文”，报文使用 `example.test` 和 `X-Gaga-Sample: synthetic`，本地静态分析不发送请求。
- 请求、响应及告警草稿按事件保存在本次客户端会话中；A→B→A 恢复各自草稿。未新增重启后草稿恢复功能。
- HTTP 归档在开始时捕获事件 ID，后续归档使用该事件。

## 实际验证

- 60 项 Rust 测试通过，0 失败；包含本次新增的无尾部空行、BOM / 空白保留、错误侧定位，以及原有 HTTP 解码、有界解压、归档与报告等检查。
- 新构建的真实 Tauri WebView 完成 **20 项 HTTP 操作检查**：填入示例、错误响应、输入保留、错误实际可见、已有结果后失败时错误仍可见且不产生重复证据、修正后重试、请求 / 响应归档、本地分析过程、事件草稿隔离、缺少响应及 AI 材料准备。
- 退出测试客户端后重新打开 SQLite，完成 **7 项持久化 / 归档检查**：两个事件资料归属、原文件 Hash、两侧原文保留、无残留临时文件及成功过程记录。
- TypeScript / Vite、macOS Tauri app 打包、Prettier 和 rustfmt 检查通过。

原生测试使用输入控件事件驱动，实际调用 Rust 并写入真实本地 SQLite；没有浏览器 IPC mock。没有自动执行操作系统剪贴板 ⌘V / Ctrl+V，没有调用云模型，没有运行恶意样本。

复现命令（源码根目录，构建 debug app 后）：

```sh
cargo test --manifest-path src-tauri/Cargo.toml --offline
node tests/native-http.mjs /absolute/path/to/debug-app/Contents/MacOS/gaga-security-assistant
```

`--http-ui` 为 debug 专项验收入口，使用独立临时工作区。正常使用应通过应用打开工作区。

## 使用与边界

进入“研判工作台 → HTTP 报文分析”，可以直接粘贴请求包与响应包；响应可以缺省。空编辑器可点“填入测试报文 → 开始分析”。真正的正文需与头字段用空行分隔。

客户端仍为开发预览版。本次修复不代表 Windows、真实 CAPE VM、内核 eBPF、四家云模型或其余已记录 UX 缺陷完成了验收。PDF、情报服务与长期数据管理等既有限制仍见 0.6.0 审计报告。

新客户端的预览工作区仅含本轮合成 HTTP 测试事件；原 0.6.0 窗口及工作区保留，避免丢失用户当前尚未归档的输入。

本轮验收数据：`gaga-http-verification-0.6.1.json`。
