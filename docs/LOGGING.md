# 运行日志与错误定位 · 0.7.9

入口：**设置 → 运行日志**。支持最近 200 条、按错误/记录 ID/任务 ID 搜索、级别筛选、刷新、复制单条，以及导出错误索引。报告失败显示可查询的任务 ID；日志详情及复制文本保留关联 ID。日志独立于事件 SQLite；数据库启动失败时仍可调用日志接口。

## 保存与字段

使用 Tauri `app_log_dir()/runtime`，macOS 一般在用户 Library/Logs 下的应用标识目录；以日志页展开显示的真实位置为准。验收模式使用独立临时工作区的 runtime-logs，不写使用者正式日志。

JSONL 轮转文件 `runtime-0.jsonl` 至 `runtime-4.jsonl`，每份最大 2 MiB，总上限 10 MiB。单条有 ID、UTC 时间、level、component、code、message、脱敏内容 fingerprint 和可选 UUID contextId。报告后台任务使用原任务 ID，方便关联一次失败与后续重试。

只有相同任务、级别及内容在 2 秒内连续出现才合并，本次合并数量显示在界面；成功写入并同步后才更新去重缓存。写失败不会吞掉首次重试；恢复成功后清除当前写入异常。轮转会淘汰旧记录，不是永久审计归档。重启保留轮转文件，去重计数重置。读取跳过坏行；追加前补齐末尾换行，避免半条旧记录吞掉重启后的第一条新记录。新 Unix 日志目录 0700、文件 0600；当前用户或管理员仍可读取修改。

正式日志位于当前本机用户的应用日志目录，多个客户端进程共享，按任务 ID 关联，不是按事件分库。`journal.lock` 以操作系统文件锁串行追加、轮转和读取，进程退出后锁由系统释放；竞争超过 250 ms 明确返回异常，不无限阻塞。调试验收仍使用独立临时日志目录。本轮用真实子进程验证锁竞争和释放后重试。

## 覆盖范围

| 来源 | 当前记录 |
| --- | --- |
| 启动 | 客户端启动、工作区就绪、失败阶段与错误 |
| 界面 | bridge 中业务 IPC 拒绝、全局 error / unhandledrejection、React 错误边界 |
| 报告 | HTML/DOCX 后台任务成功、失败、取消及任务 ID；PDF 查询失败和写水印结果 |
| 后台 | 资产巡检及自动 AI 异常、沙箱/隔离分析任务错误、Agent HTTPS 接收失败 |
| 安全限制 | 外部主窗口导航拒绝、局域网协议拒绝 |

不记录 IPC 参数或成功响应、原始报文、样本内容和模型正文。正常运行消息并非所有函数的调用追踪；没有将所有 Rust Result 在全局拦截。系统打印对话框只能知道是否成功打开，无法知道保存/取消/打印机结果。

在日志初始化之前的原生退出、SIGKILL、断电、操作系统进程崩溃或磁盘不可写时，不能保证最后一条记录落盘。panic hook 在可取得日志锁时尽力保存，不保证拦截原生崩溃。日志自己的读写失败避免递归上报；界面显示日志读取或写入异常，需检查权限与磁盘。日志是排错工具，不是不可篡改的安全审计系统。

## 隐私与反馈

写入前遮盖常见 Authorization / Cookie / API Key / token / password / Bearer / sk- 字符串、HTTP URL 和常见用户路径，限制单条长度。规则不能识别所有业务秘密；错误正文仍可能包含未匹配路径、标识或敏感摘要。复制单条前需检查，完整本地日志按客户资料保管。

“导出错误索引”只导出最近读取到的最多 200 条 ID、时间、级别、component、code、fingerprint，**不含 message、contextId 或本机目录**；不是全量日志导出。使用新文件名，完整写入并同步临时文件后排他发布，已有文件不覆盖。它用于先对齐版本/记录，再按需要核对和复制单条错误。原“数据与维护 → 导出脱敏诊断”继续只用白名单字段，不额外混入运行日志正文或客户证据。

建议反馈时提供：客户端版本、macOS 版本、操作步骤、错误索引，以及已核对的相关单条错误。不要上传工作区数据库、完整备份、聊天身份文件或真实样本来代替诊断。源码发布检查拦截 runtime-logs 与 runtime-N.jsonl，即使强制 Git 跟踪也不读取并公开正文。
