# 0.7.4：自由报告、正式入口清理与 Mac 验收

2026-10-29，Apple Silicon macOS。本阶段先完善可在现有 Mac 验证的流程，Windows / CAPE 保留为未验收项，待对应环境可用再推进。跨平台定位不变。

## 本轮改动

正式界面移除“填入测试报文”“分析内置示例”和创建演示事件入口，HTTP 使用用户复制/加载的请求与响应。普通工作区的相关后端注入命令也拒绝执行；显式 debug 隔离验收仍可使用开发夹具。历史已标记的演示事件保留来源，避免将旧材料误作真实调查。

报告从空白章节开始，可按阶段、资产、子事件自由编排，支持两级、64 节、标题正文、人员、时间和状态，主章节排序带上子树，子章节可换主章节。五步处置和入侵阶段仅作为可选追加模板，旧五步报告自动迁入章节。节点可跨章节引用，删除章节不删除证据/截图；纯人工正文可先导出并保留举证待补说明。HTML/DOCX 保留章节、子章节及举证的标题层级。设计见 [报告 C4](C4-reports-0.7.4.md)。

代码审阅发现巡检和采集历史的常用筛选缺少索引。为资产到期领取、单资产快照、事件观测、队列状态、AI 预算和采集历史增加十个索引；事件资产读取改为明确的 case_id 条件。索引在已有工作区打开时幂等补齐，首次创建仍需要时间和磁盘空间。

原生测试启动器增加实际客户端 PID 存活、启动器退出码及信号诊断。平台后台阶段同时核对实际进程，避免只观察 open 命令的退出状态。导航测试可使用有明确合成标记的累计数据空间，并比较测试前后证据、节点及 AI 数量，避免只验证空工作区。

## 累计数据验证

显式 Rust 压力测试写入 100 个独立事件、2000 份真实小文本归档、1000 个节点、1000 个关闭的资产，以及各 100000 条快照和观测。摘要、时间戳与记录都是人工构造；多条快照引用同一小原件，不能代表真实巡检生成的完整原件规模，也不是检测准确率测试。没有执行数月的墙钟时间。

调用相同 Rust 业务查询，比较无本轮索引与补齐后的全部返回结果，再验证一致快照备份、恢复到新目录、原空间及恢复空间 SQLite integrity / FK 和重启。每事件只取到本事件数据；快照最近 30 条、观测最近 200 条；未授权 AI 保持关闭。

本机开发构建，每项连续测五次取中位数，以下包含预热，不能代表冷启动、端到端 UI 延迟或其他硬件：

| 操作 | 无本轮索引 | 补齐索引 |
|---|---:|---:|
| 单资产最近快照 | 13.25 ms | 0.22 ms |
| 事件最近观测 | 14.71 ms | 1.20 ms |
| 队列统计 | 37.76 ms | 3.34 ms |
| 当前事件仪表盘 | 33.81 ms | 3.49 ms |

最终源码复跑时，索引构建约 266 ms；备份约 12.50 秒，恢复约 13.38 秒。后两者包含数据库和 2000 份小原件的校验，并不代表大文件/大截图备份耗时。原始测量在交付 storage.json 中。

## 验证范围与待补项

107 项常规 Rust 测试通过，另显式执行 1 项累计数据压力测试；常规命令将其标为 ignored，以避免默认测试不经意写入累计数据。Clippy -D warnings、格式、TypeScript/Vite 构建、18 项前端状态断言及源码卫生检查通过。原生结果在随交付 verification.json 中逐项列出。

自由报告原生专项首轮 17 项、重启 5 项、物理产物 11 项通过：两阶段/两子事件、不同负责人、同节点复用、改归属、主子树排序、删除确认、保留举证、空模板删除、独立事件、纯正文导出及两主题 960×660 窗口。对实际 HTML 和 DOCX ZIP/XML、嵌图、原件份数、数据库 integrity/FK 进行核对，未调用官方模型。

验收过程中曾使用后台 Launch Services 启动参数，导致 WebView 定时器明显延迟；恢复前台启动后通过。独立验收窗口现标注“自动验收（独立临时数据）”。这与旧版未知退出不是同一问题。HTTP 专项第一遍的测试输入带完整空行，却仍期待缺空行告警；已改回刻意省略空行的报文并重新执行，未放松产品分析规则。

最终构建访问 Documents 内的合成工作区时出现一次启动等待。进程采样停在 `Store::open -> OpenOptions::open -> __open`；同一 PID 的 macOS TCC 日志明确记录新构建签名与既有权限要求不匹配，随后 `kTCCServiceSystemPolicyDocumentsFolder` 授权提示处于等待。未修改系统权限，也未绕过授权。停止该验收进程后，将同一合成记录复制到独立临时目录，115 项导航检查通过；后续启动复跑使用该临时副本。分发记录中的 `startup-path-diagnostic.json` 保留脱敏定位结果。此结果不能用于宣称较早 0.7.3 退出根因相同；正式发行仍需稳定签名、公证及新机器验证，用户选择受保护目录时需相应系统授权。

现有流程原生回归 182 项、持久化 11 项通过，包含实际本地测试服务传输、固定证书 TLS 回传与十资产两轮后台调度；本地固定响应不代表官方模型效果。Docker/报告恢复专项首轮 36 项、重启 5 项通过，核对未确认草稿恢复、冲突选择、截图粘贴、原件篡改后拒绝导出、旧输出保留和备份恢复；Pi 在请求官方模型前取消，未读取真实模型 Key。

截图专项通过真实 WebView 的 `ClipboardEvent` 输入合成图片，核对归档 Hash、图注与导出图片像素；没有操作系统剪贴板的按键自动化。输入图片、HTTP 报文与所有压力记录均为明确标记的合成材料，交付客户端和源码包不携带这些临时工作区。

最终二进制在累计数据临时副本完成四次启动：直接启动和 Launch Services 各两次，每次 30 秒、30 次存活/数据探测，均通过，随后核对完整性、外键及 20 万条历史记录。此为短时重复启动结果，不是长期连续稳定性证明。

0.7.3 首次后台启动退出仍未确认根因，当时没有记录退出码/信号，也未找到同一时刻的客户端崩溃报告。新诊断与短时复跑结果只能说明本次条件，不能据此宣称根因已修复或长期稳定。

本轮没有读取真实模型 Key、请求官方模型、执行真实恶意样本，也没有验收 Windows / CAPE。DeepSeek 官方结果仍为 0.7.0 历史；0.7.2 钥匙串授权超时在请求前失败。当前只有 Mac 不意味着能自动验收 Windows，也不意味着 Linux eBPF 在 macOS 原生内核运行；Linux 相关历史实测发生在 Docker Desktop 的 Linux 虚拟机中。

现有核心功能边界继续以 release-manifest、[0.7.3 审计](AUDIT-0.7.3.md) 和历史验收为准。此次重跑 1 GiB 原件报告专项，首轮 15 项、重启 3 项、物理产物 10 项通过，包括真实校验进度、后台切页/切事件、取消保留原输出与完成导出。未重跑全部 Pi 深度案例；没有重扫依赖公告数据库，0.7.0 的五个 Rust 包公告匹配仍保留。macOS 为 ad-hoc 签名开发包，未 Apple 公证；工作区仍为明文，长期自动清理、工作台全量分页、备份/导入进度取消和长期连续运行验收仍未完成。

测试夹具首次编译引用了未引入的 tempfile，改为项目已有的 UUID 临时目录；首次备份因人工构造证据 ID 不是 UUID 被正确拒绝，修正夹具后整套重跑，未放松产品校验。失败日志保留于随交付记录。

## 复现

```sh
cargo test --locked --manifest-path src-tauri/Cargo.toml
GAGA_STORAGE_AUDIT_ROOT=/absolute/new-test-folder/workspace \
  cargo test --locked --manifest-path src-tauri/Cargo.toml \
  accumulated_storage_and_restore -- --ignored --nocapture
npm run desktop:build:mac-dev
node tests/native-navigation.mjs /absolute/debug-app-executable /absolute/new-test-folder/workspace
node tests/native-platform.mjs /absolute/debug-app-executable
node tests/native-report-structure.mjs /absolute/debug-app-executable /absolute/results-folder
node tests/native-mac-soak.mjs /absolute/debug-app-executable /absolute/new-test-folder/workspace /absolute/results-folder
```

只向新建测试目录运行。累计数据测试写入物理文件，备份/恢复会额外占用磁盘；测试没有自动删除成功夹具，便于复查。所有原生 GUI 验收串行执行，避免窗口/钥匙串上下文互相影响。
