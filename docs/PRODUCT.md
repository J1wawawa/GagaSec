# 产品定位与范围

嘎嘎安全助手 / J4team：**面向防御团队、运行在个人 PC 上的一站式安全终端**。

个人电脑承载统一调查工作区，连接授权目标的采集 Agent、专用沙箱与四家官方 AI。团队成员用它完成分析、记录处置和报告交付；当前“团队”描述使用人群，不代表已经实现在线协作、组织权限或身份认证。

核心流程是：建立独立事件 → 导入与分析材料 → 人工及 AI 复核 → 时间线举证与处置记录 → 编辑报告并交付。事件之间隔离证据和报告，全局情报库共享 IOC 来源及人工分类。负责人姓名是记录字段，不能当作已认证签名。

首批使用场景：HTTP 请求/响应研判、访问与系统日志排查、隔离静态样本检查、Agent 固定元数据采集、重点资产页面巡检、IOC 与黑白名单整理、按阶段、资产与子事件自由编排的事件报告。

客户端运行期间才执行定时巡检。真实目标主机的 eBPF 需要对应内核与权限；CAPE 需要独立部署 Windows 虚拟机；普通 Docker 不能等同于安全沙箱 VM。当前版本的能力与验证状态统一维护在 src/release-manifest.json，设置页面和诊断文件使用同一份清单。

优先级依次为证据真实性、隔离边界、数据可靠性、核心流程便捷性、分析覆盖和扩展能力。原始材料、规则观察、AI 推测与人工处置分别呈现；失败、未知、未覆盖和未命中必须区分。当前许可为源码公开、非商用免费、商用需授权的自定义许可，不使用 AGPL 或 OSI 开源标识。

0.7.2 将隐私控制放在独立设置页和工具栏：工作区 AI 外发锁拦截新的模型请求，锁定停用自动 AI，解锁需重新授权。自动 AI 同时只授权一个事件，且只接收本次启用后新增的观测；历史材料保留人工选择。切换事件不会扩大原授权，已授权事件可以继续后台分析新观测。范围和其他联网行为见 [PRIVACY.md](../PRIVACY.md)。

社区使用优先保证无 Key 的本地核心流程、可预览的外发材料、可恢复的本机数据、透明的能力状态和可复现的发布检查。下一阶段优先考虑多事件分页、长任务进度/取消、离线规则包版本管理与可审阅的分享包，不以增加模块数量替代核心流程质量。

0.7.3 首先补上报告导出这一长任务：后台运行、显式事件快照、实际原件校验进度、提交前取消和旧输出保留。它只优化报告读取与交付；全工作台分页、备份和日志导入的进度/取消仍待后续实现。

0.7.4 按当前只有 Mac 的条件安排验收。优先验证 macOS 原生交互、已有模型连接、Docker Desktop 无害样本流程、采集回收、累计数据、报告和备份恢复；没有可用凭据的官方模型保留待验收。Windows 客户端 / CAPE 暂不作为本阶段完成条件，待环境可用再单独验收。跨平台源码和明确未验收标记继续保留。
