# 调研成果与实施清单

定位：嘎嘎安全助手 / J4team，个人 PC 上的一站式防御调查终端。基线为 0.8.0；本次从调研进入实施，首批版本 0.9.0。建议和已交付能力分开记录，后续版本逐项更新验收证据。

## 两轮调研依据

第一轮覆盖 Wireshark、DFIR-IRIS、Timesketch、Velociraptor、CyberChef、Hayabusa、Chainsaw、CAPE、MISP、Falco，来源与差距见[调研报告](BLUE-TEAM-DESIGN-RESEARCH-2026-10-30.md)。

第二轮核对 [ABC_123 / BlueTeamTools](https://github.com/abc123info/BlueTeamTools)。读取到的公开 main 提交为 `4c2413f1401720ca8a635375247a7dd3ca515cfa`，树中只有 README.md，没有算法实现或明确许可证。本轮参考公开功能说明，独立实现相应防御流程；没有下载或运行其发行程序，没有复制实现代码，也不将其描述为已审计的开源算法。

其说明中最值得吸收的是：复杂编码按步骤处理；内存马材料与 Java 类信息联动；请求和响应一起分析；解密后识别文件类型并保留结果；搜索、导出、失败提示和不同分辨率适配。这些是功能思路，文档声称的解密能力没有在本项目中自动获得。

补充研究：[蓝队调查与官方情报 API 接入](THREAT-INTELLIGENCE-API-RESEARCH-2026-10-30.md)已核对微步、VirusTotal、RDAP、AbuseIPDB 等官方公开文档，并梳理查询/提交边界、授权、额度与报告举证。0.10.0 已实现首批只读适配器、设置、队列、缓存与报告举证，见[能力说明](THREAT-INTELLIGENCE-0.10.0.md)；仍未执行带 Key 的正式接口验收，不属于 0.9.0 已交付功能。

## 首批设计取舍

WebShell 采取有界常量求值与词法线索，先解决被简单多层编码隐藏的内容及举证困难。原始文件不修改，每个派生层有输入/输出 SHA-256、父层、来源表达式所属层、行号和字节范围。界面保存有界预览和摘要，完整派生字节仅在隔离工作器处理期间存在，不能把预览当成完整导出文件。

不执行样本、自定义函数、PHP/JS/JVM 运行时或反序列化。分支、作用域、跨文件和运行时输入属于覆盖缺口；“输入→敏感调用”是词法关联线索，不是已证明可利用的污点路径。受控静态展开也受 3 秒预算、深度 8、最多 48 层、单层 1 MiB 与累计 4 MiB 限制。

Java 类只读头和常量池，识别服务端接口、类加载与进程相关字符串，无法证明类被加载、内存马存在或攻击成功。对加密流量不会缺少密钥却声称已经解密，反编译和具体流量变种适配留在后续独立验收。

许可继续为个人及非商用免费、商用须 J4team 单独授权。引入其他项目代码或引擎时逐项审阅许可；本轮新增实现来自本项目。
