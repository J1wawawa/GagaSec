# 嘎嘎安全助手 · UX 深度复核与润色

日期：2026-11-01。对象：迁移后的 macOS 客户端 0.10.1。目标是让调查员在长时间取证、分析和写报告时少丢上下文、少被弹窗打断，输入和结果之间的关系始终清楚。

## 调研结论

结合本项目既有的蓝队产品调研（Wireshark 的列表与详情联动、Timesketch 的时间线、DFIR-IRIS 的事件责任与报告、Velociraptor 的采集上下文、CyberChef 的分层变换），当前客户端最值得持续坚持的交互原则是：

1. **材料优先**：正文、报文、原文和代码拥有稳定的大空间，说明、限制和高级选项按需展开。
2. **状态可见但不打断**：完成、失败、进行中都要能找到；成功不弹强制对话框，失败必须保留错误位置和任务 ID。
3. **事件边界明确**：切换事件、切换证据、切换模块时，不沿用旧的 IOC、筛选、草稿或异步结果。
4. **证据可回到原文**：规则、AI、时间线和报告都是派生层；原始材料、哈希、来源和限制不能被摘要替代。
5. **渐进披露**：常用动作直接可见，工具搜索、摘要过程、证据库和报告目录按需打开，避免工作台被面板挤满。

这些原则比增加更多卡片或动画更能影响日常效率。黑白主题继续保持低对比装饰、高对比文字和清晰焦点；动画只用于进入和状态变化，并服从系统减少动态效果设置。

## 本轮实际调整

### 操作完成反馈

主工作区新增右下角轻量状态提示：

- `HTTP 联合分析完成`、文件加载、报告任务等完成状态显示约 3.2 秒；
- 失败状态使用错误色和警示图标；
- 不打开模态框、不抢输入焦点、不改变页面高度；
- 底部状态栏继续保留持久状态，分析任务和报告导出仍可点击查看详情；
- `aria-live="polite"` 让辅助技术能读到结果，减少动态内容造成的打断。

这解决了“提交后不知道是否完成”和“长页面底部状态被忽略”两个高频反馈问题。它只消费已有的真实 `status` 状态，不新增假进度，也不把打开窗口视为任务完成。

### 输入与报告空间

报告正文、HTTP 请求/响应、告警、AI 材料、举证说明、处置动作和执行回执继续使用统一的多行编辑器；「放大编辑」只同步当前表单，不自动保存或发送。报告保持独立整页，复杂事件可以按主阶段、资产和子事件自由编排。

### 层级和长任务

顶部导航按工作区分组，当前组只显示相关的二级工具；`⌘K / Ctrl+K` 可以按任务搜索全部功能。日志、WebShell、样本和报告任务在切页后保留任务抽屉、状态和错误 ID。历史证据和时间线超过阈值时由后端分页，避免一次把大数据装入前端。

## 实机验证

- 原生客户端：185 项通过，72 组布局检查，960×660、1180×760、1320×860 三种窗口尺寸均覆盖浅色/深色主题；无错误。
- HTTP 流程实际输入请求包和响应包，确认双侧证据归档，并在结果页截图确认“HTTP 联合分析完成”提示可见。
- 报告专项：32 项首次编辑、5 项重启恢复、11 项实际 HTML/DOCX 文件检查通过。
- Rust：171 项通过、0 失败、4 项显式忽略；多行处置说明和回执回归通过。
- 前端生产构建、格式检查、UI 状态断言、源码卫生、IPC 文档一致性和 Tauri 安全检查通过。

本轮仍是 Apple Silicon macOS 实测；没有把 Windows/CAPE、四家官方模型联网、跨设备 P2P 或真实目标主机 eBPF 写成已验收能力。所有验收使用独立临时 SQLite，不读取模型 Key、不执行恶意样本，也不修改用户事件。
