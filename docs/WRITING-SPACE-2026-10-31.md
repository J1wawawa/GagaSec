# 编写空间调整与实际验收

2026-10-31，0.10.1，Apple Silicon macOS 原生客户端。

## 使用体验

把主要空间分配给需要人工填写的内容。短字段保留单行；调查说明、报文、材料与报告正文使用统一的多行编辑组件。

| 内容 | 默认空间与操作 |
| --- | --- |
| 危害概述、事件摘要、举证说明、图注、AI 问题和处置备注 | 至少 180px，可拖动底边增高 |
| 资产/IOC 导入、AI 材料、处置说明、执行回执、失败原因、回滚和恢复验证 | 至少 260px；导入页优先分配宽度给输入区 |
| 报告章节正文 | 至少 320px，随窗口高度增加；继续使用独立报告页面 |
| HTTP 请求/响应、告警原文 | 占用输入面板剩余空间，保留分别加载文件的入口 |
| 局域网消息 | 加大输入区，长消息可放大编写；群消息使用多行窗口 |

输入区右上角「放大编辑」打开接近整个窗口的编辑区，保留当前文字、字符限制和光标位置；完成或 Esc 返回原输入区。文字直接同步，打开/关闭编辑区不额外保存或提交；原工作流仍负责报告自动保存、表单保存和消息发送。HTTP 报文使用等宽字体，普通说明使用正文文字。

新增处置动作及记录回执的窗口最大宽度 920px。需要编写较多内容的通用宽窗口最大 1000px；小窗口限制在可视范围。节点举证窗口为说明区域分配更多宽度，报告仍保留按需打开的章节目录。

## 实际发现并修复的问题

1. 处置后端把回车当成非法控制字符，多行说明与回执会被拒绝。多行字段现允许 CR/LF/Tab，仍检查非空、长度和其他控制字符；标题、人员、目标仍按单行校验。
2. 旧通用弹窗宽度覆盖了处置窗口宽度。使用明确的处置窗口选择器修正，并在原生验收中检查实际可见宽度。
3. 成功回执、失败原因、回滚方案和恢复验证原先使用系统单行提示框。现用多行表单，确认前不推进处置状态；状态已保存而补充材料失败时，重试只保存缺失材料。

## 代码与验证入口

- `src/TextEditor.tsx` / `src/text-editor.css`：共享编辑组件，复用现有 Modal 的焦点、Esc、嵌套与背景禁用行为。
- `src/ResponseActions.tsx` / `src-tauri/src/response_actions.rs`：多行处置表单与后端校验。
- `src-tauri/tests/comfort-ui.js`：真实 WebView 输入长文本、返回后保留内容/焦点、确认前状态不变、多行回执和恢复验证实际写入数据库。
- `tests/native-comfort.mjs`：独立临时工作区，原生窗口截图与尺寸检查。
- `tests/native-report-structure.mjs`：章节、事件隔离、重启恢复及实际 HTML/DOCX 嵌图验证。

## 本轮实际结果

- [原生客户端验收](verification/writing-space-2026-10-31/native-comfort.json)：184 项通过，72 组窗口/主题布局，24 张原生截图，无错误。三种窗口为 960×660、1180×760、1320×860，均覆盖浅色/深色。
- [报告专项](verification/writing-space-2026-10-31/report-structure.json)：首次 32 项、重启 5 项、实际文件检查 11 项通过，覆盖多阶段/子事件、独立负责人、图片、HTML/DOCX 和事件隔离。
- Rust：171 通过、0 失败、4 项显式忽略。新增多行字段允许正常空白、拒绝隐藏控制字符的回归。25 项前端状态断言、生产构建、Clippy、格式、IPC 文档、源码卫生与 Tauri 安全配置检查通过。[检查汇总](verification/writing-space-2026-10-31/checks.json)。
